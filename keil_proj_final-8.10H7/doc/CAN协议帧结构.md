### CAN协议帧结构
## 分类
   1. - CAN1.0与CAN2.0(版本区别)。
      - CAN2.0A与CAN2.0B
  
**主要区别**: 
- CAN2.0A：只支持 11 位标准 ID（兼容 CAN1.0）.
- CAN2.0B：同时支持 11 位标准 ID + 29 位扩展 ID.
## 以CAN2.0B为例的帧结构简介
  1. **核心特点**
     **两种标识符格式共存**
- IDE=0：标准帧，11bit ID，兼容 CAN2.0A/CAN1.0；
- IDE=1：扩展帧，29bit ID（11+18），报文 ID 数量极大，适合总线上节点多的场景。扩展帧新增字段：SRR位、IDE位、18 位扩展 ID 段。

2. **标准数据帧完整字段**

| 字段 | 比特长度 | 说明 |
|---|---|---|
| SOF 帧起始 | 1 | 显性0，标记帧开始 |
| ID10~ID0 | 11 | 标准帧标识符，共11位 |
| RTR 远程请求位 | 1 | 0=数据帧；1=远程帧（无数据段） |
| r1、r0 保留位 | 2 | 必须置显性0 |
| DLC 数据长度码 | 4 | 0‑8，代表后续数据字节数量 |
| Data 数据场 | 0‑64 bit(0‑8B) | 有效载荷，最大8字节 |
| CRC序列 | 15 bit | CRC‑15，校验SOF至Data域 |
| CRC界定符 | 1 bit | 固定隐性1 |
| ACK位 | 1 bit | 发送方发1；接收正确拉为0应答 |
| ACK界定符 | 1 bit | 固定隐性1 |
| EOF 帧结束 | 7 bit | 全部隐性1，帧结束 |

**注意**：
- 远程帧 RTR=1，没有Data数据段。

3. **CRC校准与作业的区别**
   
|对比项|CAN CRC‑15‑CAN|作业8位累加校验和|
|---|---|---|
|算法|多项式按bit运算|字节算术加法，取低8位|
|校验位长度|15 bit|8 bit|
|实现|CAN硬件自动完成|软件代码手动计算|
|检错能力|强，大部分单/多比特错误都能检出|弱，存在漏检可能性|
|参与数据|SOF到Data所有比特|自定义头部+载荷字节|
|错误处理|硬件标记错误，自动发送错误帧|软件判断，上层处理丢包|
